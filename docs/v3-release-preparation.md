# V3.0.0 release preparation

**State:** prepared locally; final human acceptance, integration and publication pending.

## Scope

Methodology 3.0.0/LTE and portable skill 2.0.0. Include the raw V3 baseline,
canonical local engines, state/governance/Collection/Chunk/Artifact contracts,
progressive disclosure, Package/authority contracts and bounded operational
metadata. These are methodological capabilities; each runtime operation still
requires its own actor, authorization, privacy and adapter capability.

The demonstrated runtime is a bounded local Python/Git persistence adapter.
Other host adapters are portable instructions, not tested universal remote
enforcement. No global installation, ACL changes, remote transfer or automatic
existing-vault adoption is included. Publishing the methodology is separate
from migrating the remaining content.

## Evidence boundaries

- Synthetic structure and adversarial fixtures: deterministic properties.
- Synthetic content in real Git: migration/reload/recovery and containment.
- Actual private pilots: three accepted items passed preflight, CRUD write and
  fresh reload; complete original-body/legacy-field and preimage conservation.
- Experimental skill runtime: authorized local READ/Search and restricted
  disclosure behavior; not evidence of host-wide deployment.
- Actual restoration: not executed; an exact-ticket human gate remains.
- Vault adoption: 335 reviewed items remain held; no whole-vault V3 claim.

Private details stay in their owning vault. Aggregate pilot evidence is
projected in v3-migration-execution.md. Historical rc.1 reviews bind only that
unchanged package. The canonical 2.0.0 package requires fresh reviews.

## Release gates

Freeze content and package hashes; run repository/contract/package/scaffold,
negative and integrated engine checks. Primary AI review and independent AI
challenge precede exact final human approval. Create a later evidence-only
commit and verify ancestry and diff. Integrate through a reviewed PR to main,
verify actual main content and CI, then complete the exact English GitHub form.
The human creates the immutable tag and GitHub Release together. A local
release-preparation check never proves these remote events occurred.

## Recovery and adoption

MIGRATIONS.md and v3-migration-execution.md govern per-vault preparation,
accepted item mappings, cumulative Collections, source/context hashes,
canonical apply and exact-ticket recovery. An unknown source version stays
unknown. Reconcile partial effects before any reexecution. Existing V2
instances can continue with the appropriate immutable V2 package while their
V3 migrations remain unaccepted. Never weaken local vault restrictions.

## Immutable package declaration

The stable manifest declares an immutable-release-target with exact intended tag/path. This is not a publication claim. The target declaration is kept unchanged when publication later happens, avoiding a package-hash/review cycle. A source_commit null is explicitly unverified; the operator must resolve the actual published tag and verify its exact commit and file hashes. The release validator checks local package/review readiness only; actual main, CI, approval, tag absence and publication remain separate external gates.
