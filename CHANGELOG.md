# Hipocampo — Changelog

Version history of the methodology itself. Follows [SemVer](https://semver.org/lang/pt-BR/) — see SPEC.md, section 9.

## [Unreleased]

### Added
- **Progressive privacy, licensing boundaries, intent routing, and skill-package integrity** (`changes/0053-progressive-privacy-licensing-and-skill-integrity`) — new content and content touched by CRUD/REM must not retain credentials or non-public financial values; public financial values carry a public URL/date citation; remediation is progressive rather than an update-triggered full vault sweep. The structural audit gains privacy/security/provenance as a core criterion, public methodology material remains anonymized, and `LICENSE` boundaries distinguish Apache-2.0 methodology tooling from proprietary content vaults. `AGENTS.md` now routes common user intents, contribution requires terminology review, and the skill publishes a versioned package lock for confirmed client-side updates.
- **v2.1.0 consistency contracts and Codex distribution** (`changes/0052-consistency-contracts-and-codex-distribution`) — anchor manifests can register operator-confirmed repository addresses without restoring a client-side router; target manifests remain authoritative for entity, role, and scope. New manifests use `instance.policy_profile` for sensitive-data policy and `instance.curation_level` for repository curation, resolving the former `tier` collision while preserving read compatibility with v2 manifests. The canonical skill is 1.1.0, includes invariant 6 and a declared Codex adapter, and a new CI validator checks these contracts across specification, scaffold, skill, and disclosures.
- **CI enforcement of repository structure, skill-doc consistency, and Change Set validation** (`changes/0050-ci-and-change-set-validation`) — `.github/workflows/validate.yml` (new) runs `scripts/validate_hipocampo.py`, the new `scripts/validate_skill_docs.py`, and the new `scripts/validate_change.py` on every PR against `main` and on push to `main`. `scripts/validate_skill_docs.py` checks `skill/**.md`'s `example/*.md` output-path literals against `scaffold/profiles/*.yaml`'s declared outputs, and flags any leftover use of the superseded `domain:` field under `skill/` (`decisions/0041`). `scripts/validate_change.py` validates every `changes/*/impact.yaml`'s own schema and, in PR mode, checks that a protected path changed in the diff is covered by an `updated` `impact[]` entry in a Change Set touched by the same diff — closing the gap `docs/change-management.md` previously described as "no deterministic validation compares this against the actual diff yet." `requirements-dev.txt` (new) pins PyYAML for the one script that needs it.

- **`decisions/0050-no-nominal-entity-citation-in-methodology-repository.md`** (new) — standing, unconditional rule: no real, identifiable entity, colleague, or personal account handle may be cited anywhere in this repository, in any context (worked example, evaluation scenario, Decision Record rationale, audit finding, or Change Set note); a genuinely valuable real case is kept but every identifying token is replaced with a clearly-marked anonymized placeholder.
- **Anonymization of every real-entity citation found in this repository** (`changes/0051-anonymize-nominal-entity-citations`) — `docs/evaluation-scenarios.md`, `decisions/0026-account-vs-opinion-in-corporate-instance.md`, `decisions/0039-minimal-evaluation-scenarios.md`, and `decisions/0024-upgrade-md-cumulative-checklist.md` had their real employer name, real colleague first name, and real personal account handle redacted to anonymized placeholders (`Acme`/`org-acme`, `[Colleague]`, `@personal-handle`); `skill/references/instantiation.md`'s worked example was similarly redacted. Two evidentiary artifacts normally never edited after acceptance — the frozen `audits/moda/2026-08-17-v1.0.0-self-audit.md` and the accepted `changes/0038-0039-failure-recovery-and-evaluation-scenarios/impact.yaml` — each received a narrow, logged in-place token redaction plus an appended, dated note documenting exactly what changed and why, per `decisions/0050`.

## [2.0.0] — 2026-08-19

**Scope classification: MAJOR.** Applying `decisions/0023`'s operational test to everything accumulated since v1.9.0: one change-set in this cycle — the entity model (`decisions/0040`/`0041`, `hipocampo.yaml`'s `instance.domain` → `instance.entity`/`instance.role`/`instance.scope_description`) — makes an existing instance's manifest formally incompatible with no action, satisfying the MAJOR test's own worked example ("required field renamed/removed"). Every other change-set in this cycle is `minor` per its own `impact.yaml` (confirmed by re-checking each one before cutting this release, not assumed from the "2.0.0" framing). This is what makes the release MAJOR, not the version number by itself.
