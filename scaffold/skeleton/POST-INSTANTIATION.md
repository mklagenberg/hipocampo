# Post-instantiation — verification checklist

This repository was generated by an AI agent operating the Hipocampo skill, following the declared scaffold profile (`hipocampo/scaffold/profiles/pessoal.yaml` or `empresa.yaml`) — see `hipocampo/skill/references/instantiation.md`. The agent already presented the complete plan before writing any file (invariant 5) and generated the outputs declared in the profile. This checklist exists for you to confirm the generation was done correctly before storing any real knowledge — it is no longer a manual step-by-step instantiation guide.

## 1. Confirm that the repository is private

This is not optional. It's the invariant that underpins the methodology's entire `visibility` model (`hipocampo/SPEC.md`, section 8, invariant 1). The agent should already have created the repository as private — confirm it.

## 2. Confirm the LICENSE

The agent should already have generated the `LICENSE` from the correct template (personal or corporate, `hipocampo/scaffold/license-templates/`), with the placeholders filled in from the inputs you provided. Open the file and check:

1. Name/handle (personal) or legal name (corporate) filled in correctly.
2. If this repository is at the "vault" level (only receives `visibility: confidential`/`restricted`), confirm that only sections (c) and (d) of the template were kept, per the template's own adjustment note.

## 3. Confirm the skill is installed in your AI environment

This content repository **does not** carry a `skill/` folder — the skill always runs in your AI environment (Cowork, Claude Code, etc.), per person, never per repository (`hipocampo/decisions/0025-skill-is-client-side-never-per-repository.md`). The scaffold never generates this folder.

1. Confirm that your personal copy of the skill (canonical source: [`hipocampo/skill/SKILL.md`](https://github.com/mklagenberg/hipocampo/blob/main/skill/SKILL.md) + `skill/references/*.md`) is installed in your AI environment.
2. If this new repository is your personal anchor vault (your very first vault, `hipocampo/SPEC.md` section 12-B), confirm its address is recorded per `references/personalization.md` in your copy — that pointer is the only thing that needs hand-filling; every other vault this anchor gives you access to is discovered automatically from here on (`hipocampo/SPEC.md`, section 12-A). If this is an additional vault, nothing needs updating — the next session's discovery picks it up from this vault's own `hipocampo.yaml` (`entity`/`role`/`scope_description`) with no local table to touch.
3. If you operate more than one git account that resolve to the same human author, confirm the handles are recorded in your `profile.md` (`hipocampo/SPEC.md` section 12-B) rather than in a separate table — `profile.md` lives in your personal anchor vault, not in this one, unless this repository is that anchor.

## 4. Confirm the AGENTS.md

`AGENTS.md` should already have been filled in by the agent from the collected inputs before generation — not a generic `[fill in: ...]`. Check:

- **Scope of this repository** — the two mandatory fields filled in: the **instance type** (`corporativa` or `pessoal`) and what should/shouldn't be stored here.
- **Multi-account author identity**, if applicable.
- **Local extensions to Hipocampo vX.Y** — if there's nothing to declare yet, it should be recorded as "none yet", not left blank.
- **Maintenance rituals** — cadence confirmed (default or this instance's actual adjustment).

## 5. Confirm the compatibility version

In the same `AGENTS.md`, check the "Hipocampo version followed by this instance" line — it should reflect the current version of `hipocampo/SPEC.md` at instantiation time, not an outdated value.

## 6. Confirm the `hipocampo.yaml` manifest

This repository should have a `hipocampo.yaml` at the root, generated by the agent from the scaffold profile used. Check that `instance.entity`, `instance.role`, `instance.policy_profile`, `instance.curation_level`, and `scaffold.profile` correctly reflect this instance. A legacy `instance.tier` is accepted only for a pre-2.1 manifest awaiting upgrade.

## 7. Delete or adapt the example

`example/example-note.md` exists only to illustrate the frontmatter — it isn't real content. Delete or adapt it before your first real document.

## Done

From here, follow `hipocampo/GETTING-STARTED.md` (section 3 onward) to write your first document and set up the routines (frontmatter audit, REM, structural audit), already covered by the skill you confirmed in step 3.
